# GEH Lab 업로드본

2026-09-14 최신 수정본입니다. 특허 발명자 멤버 선택과 멤버별 특허 건수·목록을 추가했습니다. 홈 사진 위 통계, 관리자 화면 수정과 Firestore 조회 캐시를 유지합니다.

## 특허 발명자와 멤버별 특허

- 관리자 → 특허 → 추가/수정에서 연구실 발명자를 검색하고 체크하세요. 목록에 없는 사람은 국문·영문 직접 입력란에 적습니다. 여러 이름은 쉼표로 구분하며, 아래 미리보기에서 표시될 발명자를 확인할 수 있습니다.
- 선택한 멤버는 이름 대신 멤버 ID로 연결합니다. 기존 이름만 저장된 특허도 현재 명단의 이름과 정확히 일치하고 동명이인이 없으면 연결합니다. 자동으로 연결되지 않은 이름은 직접 입력란에 남으므로 필요한 멤버를 체크해 주세요.
- 멤버를 클릭하면 상세 화면에 관련 특허 목록과 현재 상태별 `등록 N건`, `출원 N건`을 표시합니다. 등록된 특허를 출원 건수에 다시 포함하지 않습니다. 조회에 실패한 경우에는 0건으로 표시하지 않습니다.
- 멤버 상세 화면을 열 때 필요한 특허 데이터를 기존 10분 캐시로 불러옵니다. 공개 화면의 실시간 구독은 추가하지 않았습니다. 관리자에서 특허를 저장하면 같은 브라우저·사이트의 캐시가 갱신됩니다.

기존 `patents` 읽기·관리자 쓰기 규칙이 적용되어 있다면 Firebase 콘솔에서 컬렉션이나 필드를 추가할 필요가 없습니다. 새 연결 정보는 특허 저장 시 함께 저장됩니다. `patents` 권한 오류가 계속되면 아래의 Firebase 규칙 안내를 확인하세요.

## 이번에 줄인 Firestore 조회

- 공개 페이지는 컬렉션별 데이터를 브라우저에 10분간 보관합니다. 홈·검색·한국어·영어 페이지에서 같은 캐시와 진행 중인 요청을 재사용하며, 공개 화면의 실시간 구독을 제거했습니다.
- 관리자에서는 현재 탭과 열린 편집창에 필요한 데이터만 구독합니다. 탭을 바꾸거나 편집창을 닫으면 불필요한 구독을 해제합니다.
- 관리자 저장·삭제가 성공하면 같은 브라우저·사이트의 해당 캐시를 무효화합니다. 다른 방문자는 캐시가 만료된 뒤 최신 데이터를 받으므로, 변경 반영에 약 10분이 걸릴 수 있습니다.
- 네트워크 오류나 할당량 초과 시 마지막으로 받은 데이터를 최대 24시간까지 다시 사용하고 안내를 표시합니다. 실패한 응답을 정상적인 0건으로 저장하지 않으며, 즉시 반복 요청하지 않도록 1분 간격을 둡니다.
- 브라우저 저장소를 사용할 수 없으면 현재 페이지의 메모리 캐시로 동작합니다. 휴지통·로그인 정보는 공개 데이터 캐시에 저장하지 않습니다.

이번 캐시 적용을 위해 Firebase 콘솔에서 기능을 켜거나 컬렉션을 추가할 필요는 없습니다. 쿠키 동의창·분석용 추적 기능도 추가하지 않았습니다. 조회 제한이나 기존 보안 규칙 오류는 별도로 해결해야 하며, 캐시가 이미 발생한 사용량을 취소하지는 않습니다.

## 업로드할 내용

이 `GEH_Lab-main` 폴더 안의 **모든 파일과 하위 폴더**를 기존 GEH Lab 저장소의 최상위에 덮어써 주세요. `package.json`, `index.html`, `assets`, `en`이 기존 저장소의 같은 위치에 들어가면 됩니다.

- 페이지와 공통 파일: 현재 폴더의 HTML·JS·CSS·JSON 파일, `robots.txt`, `sitemap.xml`, `.gitignore`
- 하위 폴더: `assets`, `en`, `scripts`, `firebase`
- Vercel 설정: `vercel.json`, `vite.config.js`, `package.json`, `package-lock.json`

업로드 후 저장소에 변경을 저장하고, 연결된 Vercel 프로젝트에서 배포하면 됩니다.

특히 `index.html`과 `en/index.html`도 함께 덮어써야 합니다. `assets`만 업데이트하면 새 CSS와 예전 홈 HTML이 섞여 숫자 정보가 사진 아래에 남습니다. 저장소의 두 홈 HTML에서 `home-overview`를 검색하면 업로드가 반영됐는지 확인할 수 있습니다. 두 파일 모두 이 영역 안에 `id="hero-stat-grid"`가 있어야 합니다.

빌드가 끝나면 두 언어의 홈 배치와 CSS를 자동 검사합니다. 이전 홈 파일이 남아 있으면 오류로 빌드를 중단하므로, 파일을 맞춘 뒤 새 커밋으로 다시 배포하세요.

기존 GitHub 저장소에 `node_modules`와 `dist`가 올라가 있다면 저장소에서도 삭제해 주세요. `.gitignore`를 덮어쓰는 것만으로 이미 등록된 파일이 삭제되지는 않습니다.

## Vercel 빌드 설정

- 프로젝트 루트: `package.json`이 있는 위치
- 설치 명령: `npm ci --include=dev`
- 빌드 명령: `npm run build`
- 결과 폴더: `dist`

이 값은 `vercel.json`에 설정되어 있습니다. `node_modules`와 `dist`는 설치·빌드 과정에서 생성되므로 업로드본에서 제외했습니다.

의존성은 빌드할 때 기존 설치본을 제거하고 다시 설치합니다. Vite는 `node ./node_modules/vite/bin/vite.js`로 실행하므로 ZIP 업로드 과정에서 실행 권한이 빠져도 빌드 명령이 실행됩니다.

## Vite 실행 권한 오류 수정 시

`node_modules/.bin/vite: Permission denied`로 배포가 실패했다면 이 폴더의 `package.json`과 `vercel.json`을 기존 저장소의 같은 파일에 덮어쓰고 새 커밋으로 배포하세요. 위의 설치 명령은 이전 의존성 폴더를 새로 설치하므로 캐시된 실행 파일도 재사용하지 않습니다.

로컬에서 확인하려면 `npm ci` 후 `npm run verify`를 실행하세요. 캐시·동시 요청·저장 후 갱신·관리자 구독 검사는 실제 Firebase에 접속하지 않고 실행됩니다.

## 로컬 실행과 데이터 원본 갱신

`npm run dev`와 기본 `npm run build`는 저장소에 있는 프로필 원본을 사용하므로, 반복 빌드로 운영 Firestore를 조회하지 않습니다. localhost의 공개 화면과 관리자도 기본적으로 로컬 예제 데이터를 사용합니다. 관리자에서 저장한 예제는 해당 브라우저에만 보관됩니다.

검색엔진용 멤버 HTML의 원본을 운영 데이터로 갱신할 때만 `npm run sync:profiles`를 실행한 뒤 생성된 원본 변경을 저장소에 반영하세요. 조회와 빌드를 한 번에 실행하려면 `npm run build:sync`를 사용합니다. 이 두 명령은 운영 Firestore 읽기를 발생시키므로 할당량이 복구된 뒤 필요한 경우에만 실행하세요. 배포된 공개 화면은 기존과 같이 운영 데이터에서 최신 내용을 가져옵니다.

## 홈 특허 집계와 Firebase 규칙

홈 요약에 구성원·과제·논문·특허·게시판을 표시합니다. 특허 총계와 등록·출원 건수는 특허 페이지와 같은 데이터에서 자동 집계합니다.

특허 카드에 `—`와 조회 실패 안내가 나오고 `patents` 조회가 `Missing or insufficient permissions`로 거부된다면 Firebase의 특허 읽기 권한을 확인하세요. `firebase/firestore.rules`에는 특허 공개 조회 및 관리자 쓰기 규칙이 포함되어 있지만, GitHub 업로드나 Vercel 재배포가 Firestore 규칙을 적용하지는 않습니다.

Firebase 프로젝트의 Firestore 규칙에서 기존 관리자 권한과 다른 컬렉션 규칙을 유지하며, `match /databases/{database}/documents` 안에 아래 블록을 반영해야 합니다. `isAdmin()`은 해당 규칙 파일에 정의된 기존 관리자 확인 함수입니다.

```text
match /patents/{docId} {
  allow read: if true;
  allow write: if isAdmin();
}
```

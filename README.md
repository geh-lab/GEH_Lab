## 논문·특허 카드 구성

- 특허는 날짜·상태·국가, 제목, 전체 발명자와 원문 링크를 먼저 표시합니다. 출원인·출원번호·등록번호·날짜·요약은 `특허 상세 정보`를 펼쳐 볼 수 있습니다.
- 논문의 저자 영역 제목은 한국어·영어 페이지 모두 `Lab authors`입니다. 이름 옆 화살표를 제거했으며, 이름을 누르면 기존 프로필이 열립니다. 이름과 역할은 넓은 화면에서 가로로 이어지고 좁은 화면에서는 공간에 맞춰 줄바꿈합니다. 논문에 기재된 전체 저자 문자열은 그대로 유지합니다.
- 특허의 `연구실 발명자`도 같은 배치로 표시하며 영문 제목은 `Lab inventors`입니다. 영문 특허의 전체 발명자 줄에서도 연결된 멤버의 등록된 영문명을 사용합니다. 외부 발명자의 직접 입력 이름과 영문명이 없는 사람의 기존 이름은 유지합니다.
- 특허 페이지는 첫 응답에 연결된 멤버 정보도 포함합니다. 두 언어 모두 10분 캐시를 재사용하며 실시간 구독은 추가하지 않습니다.

## 특허 국가 선택과 관리자 건수

- 특허 추가 시 국가 기본값은 대한민국입니다. 주요 국가 다음에 나머지 국가·지역을 가나다순으로 표시하며, 유럽특허청·PCT는 별도 관할 그룹으로 선택합니다. 국가를 고르면 영문명이 자동으로 맞춰집니다.
- 기존에 직접 입력한 관할을 목록에서 찾을 수 없거나 국·영문 값이 서로 다르면 `기존값`으로 보존합니다. 다른 국가를 선택하면 해당 국가의 국·영문 값으로 변경됩니다.
- 관리자 로그인 후 멤버·과제·논문·특허·게시판·휴지통 건수가 자동으로 표시됩니다. 현재 탭은 기존 구독을 사용하고, 나머지는 Firestore 집계 쿼리로 숫자만 읽습니다. 저장·삭제·복원 후 변경된 항목도 갱신합니다.
- 집계 조회도 Firestore 읽기 사용량에 포함됩니다. 읽기 실패는 0건으로 표시하지 않으며 오류 안내를 제공합니다. 기존 컬렉션 읽기 권한이 적용되어 있다면 별도 필드·컬렉션·Firebase 설정 추가는 필요하지 않습니다.

## 특허 발명자와 멤버별 특허

- 관리자 → 특허 → 추가/수정에서 연구실 발명자를 검색하고 원하는 순서로 체크하세요. 목록에 없는 사람은 국문 성·이름과 영문 성·이름(선택)을 한 명씩 입력하고 `목록에 추가`를 누릅니다. 멤버와 직접 입력한 사람이 추가한 순서대로 하나의 목록에 쌓이며 쉼표는 자동으로 들어갑니다.
- `공보상 발명자 순서` 목록의 위·아래 화살표 버튼으로 연구실 멤버와 직접 입력한 발명자를 함께 정렬할 수 있습니다. 직접 입력한 이름은 연필 버튼으로 수정하고, × 버튼으로 목록에서 제외합니다. 아래 미리보기에서 확인한 뒤 저장하면 특허 페이지의 국문·영문 발명자와 연구실 발명자 목록에 반영됩니다. 순서 변경은 멤버 연결과 개인별 특허 건수에 영향을 주지 않습니다.
- 선택한 멤버는 이름 대신 멤버 ID로 연결합니다. 기존 이름만 저장된 특허도 현재 명단의 이름과 정확히 일치하고 동명이인이 없으면 연결합니다. 자동으로 연결되지 않은 이름은 직접 입력란에 남으므로 필요한 멤버를 체크해 주세요.
- 멤버를 클릭하면 상세 화면에 관련 특허 목록과 현재 상태별 `등록 N건`, `출원 N건`을 표시합니다. 등록된 특허를 출원 건수에 다시 포함하지 않습니다. 조회에 실패한 경우에는 0건으로 표시하지 않습니다.
- 멤버 상세 화면을 열 때 필요한 특허 데이터를 기존 10분 캐시로 불러옵니다. 공개 화면의 실시간 구독은 추가하지 않았습니다. 관리자에서 특허를 저장하면 같은 브라우저·사이트의 캐시가 갱신됩니다.

기존 `patents` 읽기·관리자 쓰기 규칙이 적용되어 있다면 Firebase 콘솔에서 컬렉션이나 필드를 추가할 필요가 없습니다. 새 연결 정보는 특허 저장 시 함께 저장됩니다. `patents` 권한 오류가 계속되면 아래의 Firebase 규칙 안내를 확인하세요.

기존 GitHub 저장소에 `node_modules`, `dist`, `.server`가 올라가 있다면 저장소에서도 삭제해 주세요. `.gitignore`를 덮어쓰는 것만으로 이미 등록된 파일이 삭제되지는 않습니다.

## Vercel 빌드 설정

- 프로젝트 루트: `package.json`이 있는 위치
- 설치 명령: `npm ci --include=dev`
- 빌드 명령: `npm run build`
- 결과 폴더: `dist`

이 값은 `vercel.json`에 설정되어 있습니다. `node_modules`, `dist`, `.server`는 설치·빌드 과정에서 생성되므로 업로드본에서 제외했습니다. 빌드 검증 후 공개 HTML 12개를 비공개 `.server` 폴더로 옮겨 Vercel 함수에 포함합니다. 정적 HTML이 서버 응답을 가리지 않도록 하는 과정입니다. `dist`만 정적 호스팅하는 방식으로는 이 버전의 공개 페이지를 제공할 수 없습니다.

의존성은 빌드할 때 기존 설치본을 제거하고 다시 설치합니다. Vite는 `node ./node_modules/vite/bin/vite.js`로 실행하므로 ZIP 업로드 과정에서 실행 권한이 빠져도 빌드 명령이 실행됩니다.

## Vite 실행 권한 오류 수정 시

`node_modules/.bin/vite: Permission denied`로 배포가 실패했다면 이 폴더의 `package.json`과 `vercel.json`을 기존 저장소의 같은 파일에 덮어쓰고 새 커밋으로 배포하세요. 위의 설치 명령은 이전 의존성 폴더를 새로 설치하므로 캐시된 실행 파일도 재사용하지 않습니다.

로컬에서 확인하려면 `npm ci` 후 `npm run verify`를 실행하세요. 캐시·동시 요청·저장 후 갱신·관리자 구독 검사는 실제 Firebase에 접속하지 않고 실행됩니다.

## 로컬 실행과 데이터 원본 갱신

`npm run dev`와 기본 `npm run build`는 저장소에 있는 프로필 원본을 사용하므로, 반복 빌드로 운영 Firestore를 조회하지 않습니다. `npm run dev`의 공개 화면과 관리자는 로컬 예제 데이터를 사용합니다. 관리자에서 저장한 예제는 해당 브라우저에만 보관됩니다.

개발용 멤버 스냅샷을 운영 데이터로 갱신할 때만 `npm run sync:profiles`를 실행한 뒤 생성된 원본 변경을 저장소에 반영하세요. 조회와 빌드를 한 번에 실행하려면 `npm run build:sync`를 사용합니다. 이 두 명령은 운영 Firestore 읽기를 발생시키므로 할당량이 복구된 뒤 필요한 경우에만 실행하세요. 배포된 공개 화면과 검색엔진이 받는 HTML은 운영 데이터로 서버에서 생성합니다. `npm run build` 후 `npm run preview`를 실행하면 같은 서버 처리를 확인할 수 있으며, 이 미리보기는 실제 공개 Firestore 읽기를 발생시킵니다.

## 홈 특허 집계와 Firebase 규칙

홈 요약에 구성원·과제·논문·특허·게시판을 표시합니다. 특허 총계와 등록·출원 건수는 특허 페이지와 같은 데이터에서 자동 집계합니다.

특허 카드에 `—`와 조회 실패 안내가 나오고 `patents` 조회가 `Missing or insufficient permissions`로 거부된다면 Firebase의 특허 읽기 권한을 확인하세요. `firebase/firestore.rules`에는 특허 공개 조회 및 관리자 쓰기 규칙이 포함되어 있지만, GitHub 업로드나 Vercel 재배포가 Firestore 규칙을 적용하지는 않습니다.

Firebase 프로젝트의 Firestore 규칙에서 기존 관리자 권한과 다른 컬렉션 규칙을 유지하며, `match /databases/{database}/documents` 안에 아래 블록을 반영해야 합니다. `isAdmin()`은 해당 규칙 파일에 정의된 기존 관리자 확인 함수입니다.

```text
match /patents/{docId} {
  allow read: if true;
  allow write: if isAdmin();
}
```
